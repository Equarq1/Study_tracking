**День 1 — настройка инфраструктуры и контрактов**

- Backend Lead: настроить Django-проект, подключить PostgreSQL, создать базовые модели (User с ролью, Category, AchievementRequest, XPLedger) и прогнать первые миграции
- Backend Dev 2: настроить DRF, базовый auth (можно начать с simple JWT или Django sessions — что команда лучше знает), создать заглушки эндпоинтов (/api/requests/, /api/auth/) хотя бы с моковыми ответами
- Frontend Lead: инициализировать React-проект (Vite), настроить роутинг (react-router), базовую структуру папок, подключить axios/fetch-клиент
- Frontend Dev 2: накидать вайрфреймы трёх ключевых экранов (форма заявки, профиль, дашборд куратора) — можно прямо в коде как статичные компоненты без логики
- AI/Integration Dev: получить доступ к Anthropic API, написать и протестировать в изоляции (отдельный скрипт) первый вариант промпта для оценки заявки — на вход текст+категория, на выход число XP и обоснование
- Дизайн/QA/DevOps: накидать простой UI-кит (цвета, шрифты, кнопки) — можно взять готовую библиотеку (MUI или Tailwind) вместо рисования с нуля, чтобы не терять время; параллельно завести задачи в трекере (Trello/Notion/GitHub Projects) для всей команды

- Финальная структура API-контракта

**Дни 2-3 — основной функционал заявки**

- Backend: эндпоинт создания заявки → вызов AI-сервиса (можно как отдельная функция/сервис-класс) → сохранение с ai_suggested_xp и статусом pending
Frontend: рабочая форма подачи заявки, подключённая к реальному API, отображение списка своих заявок у студента
AI Dev: довести промпт до стабильного формата ответа (JSON со строгой структурой, чтобы парсинг не падал), обработать случай, когда AI вернул кривой формат

**Дни 3-4 — куратор и подтверждение**

- Backend: эндпоинты для куратора — список pending-заявок, approve/reject, ручная правка XP, при approve — запись в ledger
- Frontend: дашборд куратора с этими действиями
Параллельно: агрегация XP (эндпоинт профиля, который суммирует ledger)

**День 5 — сборка вертикального среза**
Весь день — интеграция и фикс багов, чтобы к вечеру был рабочий полный цикл: регистрация → заявка → AI-оценка → проверка куратором → обновление профиля. Сделайте mini-демо внутри команды, чтобы увидеть, что реально не работает.

**Дни 6-7 — категории и визуализация профиля**

- Добавить систему 2-3 категорий, разбивку XP по ним
- Frontend: визуализация профиля (прогресс-бары или radar-диаграмма по категориям через recharts), лента ачивок-бейджей
- Backend: уровни (простая таблица порогов XP → уровень)

**День 8 — устойчивость и edge cases**

- Обработка ошибок (AI таймаут/недоступен — что показываем пользователю), валидация форм, защита эндпоинтов по ролям (студент не может видеть чужие заявки, не-куратор не может approve)
- Базовое тестирование сценариев командой QA

**День 9 — деплой и финальная полировка**

Задеплоить (Render/Railway для бэка+БД, Vercel для фронта)
Прогнать полный сценарий на проде, а не только локально — на этом этапе обычно всплывают сюрпризы с CORS, переменными окружения и т.д.
